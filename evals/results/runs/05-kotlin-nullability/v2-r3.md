```kotlin
class UserService(private val repo: UserRepository) {
    fun displayName(id: Long): String? {
        val user = repo.findById(id) ?: return null
        return user.nickname?.takeIf { it.isNotBlank() }
            ?: "${user.firstName} ${user.lastName}"
    }
}
```

**What changed**
- **Guard clause:** `if (user == null) return null` became `?: return null`, the idiomatic Kotlin form (G29-style simplification of the null check).
- **Nickname check:** `nickname != null && nickname.isNotBlank()` followed by returning it is now `nickname?.takeIf { it.isNotBlank() }`. The null and blank checks are no longer repeated, and the intent reads as "use the nickname if it's usable".
- **Fallback name:** `firstName + " " + lastName` became a string template, which is the standard Kotlin style.

**What I kept**
- The nullable `String?` return. In Kotlin, a nullable type for "not found" is idiomatic, so I didn't switch to exceptions or a `Result` type.
- The public signature and behavior are unchanged. The nickname is still returned untrimmed, and the fallback has the same format.
- The class and method names. They already say what they do.

**Not changed, since it's out of scope:** if "display name" logic is needed elsewhere, it could move to a `User.displayName()` method so the rule lives with the data. I'd only do that once a second caller exists.
