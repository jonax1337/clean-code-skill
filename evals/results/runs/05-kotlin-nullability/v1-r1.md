```kotlin
class UserService(private val repository: UserRepository) {

    fun displayName(id: Long): String {
        val user = repository.findById(id) ?: throw UserNotFoundException(id)
        return user.displayName()
    }
}

private fun User.displayName(): String =
    nickname?.takeIf { it.isNotBlank() } ?: "$firstName $lastName"

class UserNotFoundException(id: Long) : RuntimeException("User with id $id not found")
```

**What changed and why**

- **No `null` return:** `displayName` now throws `UserNotFoundException` with the id in the message, instead of returning `null` and pushing the null check onto every caller. The `null` from `findById` is handled once, at the boundary, with `?:`.
- **Separated responsibilities (G30, G34):** the function now only looks up the user. The rule for choosing between nickname and full name lives in `User.displayName()`, one level of abstraction down.
- **Simplified nickname check:** `nickname?.takeIf { it.isNotBlank() } ?: ...` replaces the nested `if` and the repeated `user.nickname` access. The string template replaces `+` concatenation.
- **Naming:** `repo` became `repository` (N1, no abbreviation).

**Caveats**

- This changes the contract. Callers that currently expect `String?` must now handle `UserNotFoundException`, or you can keep the nullable return if that's an intentional part of your API. I can't see the callers or the tests, so I haven't run or updated either.
- `User.displayName()` is a private extension only because I can't see `User`. If you can edit that class, move the method there. Logic that only uses `User`'s fields belongs on `User` (G14, Feature Envy).
- Put `UserNotFoundException` wherever your project keeps its exceptions.
