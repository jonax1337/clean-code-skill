```kotlin
class UserService(private val repo: UserRepository) {

    fun displayName(id: Long): String {
        val user = repo.findById(id) ?: throw UserNotFoundException(id)
        return user.displayName()
    }
}

class UserNotFoundException(id: Long) : RuntimeException("User with id $id not found")

fun User.displayName(): String =
    if (nickname.isNullOrBlank()) "$firstName $lastName" else nickname
```

**What changed**

- **No `null` return:** The method returned `null` for unknown users, which pushes a null check onto every caller. It now throws a `UserNotFoundException` that carries the id as context.
- **Feature envy (G14):** The rule for choosing between nickname and full name only uses `User` data, so it moves out of the service into `User.displayName()`. The service now only does lookup and delegation.
- **Condition simplified:** `nickname != null && nickname.isNotBlank()` becomes `isNullOrBlank()`, formulated once instead of a negated long form (G28, G29). The three early returns collapse into one expression.
- **String building:** `firstName + " " + lastName` becomes a string template.
