```kotlin
class UserNotFoundException(id: Long) : RuntimeException("No user found with id $id")

class UserService(private val repo: UserRepository) {

    fun displayName(id: Long): String {
        val user = repo.findById(id) ?: throw UserNotFoundException(id)
        return user.nickname?.takeIf { it.isNotBlank() } ?: fullNameOf(user)
    }

    private fun fullNameOf(user: User) = "${user.firstName} ${user.lastName}"
}
```

**What changed**

- **No `null` return:** `displayName` no longer returns `String?`. A missing user now throws `UserNotFoundException` with the id as context. Callers no longer need null checks, and the guard clause `if (user == null) return null` is gone.
- **Simplified nickname check:** `user.nickname != null && user.nickname.isNotBlank()` is now `nickname?.takeIf { it.isNotBlank() }`. This removes the double access to the property. It also avoids a smart-cast failure if `nickname` is a `var` or declared in another module.
- **Single abstraction level:** The method now reads as "load the user, then use the nickname or fall back to the full name". The string concatenation moved into `fullNameOf`, and uses a string template instead of `+`.

**Behavior change:** The old code returned `null` for an unknown id, and this version throws. If existing callers depend on `null`, update them or tell me and I'll keep a nullable variant. I couldn't see the callers, so I haven't checked them.

**Not done, since `User` isn't shown:** `fullNameOf` and the nickname rule are only about `User`'s own data, which is Feature Envy (G14). Ideally `User` would own this logic, for example as `User.displayName()`. Then `UserService` would shrink to the lookup plus `user.displayName()`.
