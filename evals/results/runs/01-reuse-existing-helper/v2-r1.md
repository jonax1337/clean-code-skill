I added `format_invoice_total`, which reuses `invoice_total` and the existing `format_currency` instead of adding a second formatter.

```diff
 def invoice_total(items) -> Decimal:
     return calc_net(items) + calc_vat(items)
+
+
+def format_invoice_total(items) -> str:
+    return format_currency(invoice_total(items))
```

- **Result:** a gross total of `1234.50` comes out as `1.234,50 EUR`. `format_currency` already rounds half-up to two decimals and swaps the separators to the German style.
- **Currency:** I didn't add a `currency` parameter, since `invoice_total` has no notion of currency and `format_currency` already defaults to `"EUR"`. If you later invoice in other currencies, the parameter can be added then.
- **Tests:** I couldn't run anything here, so this is untested. A test like `format_invoice_total([Item(price=Decimal("1037.50"), qty=1)])` should return `"1.234,63 EUR"` (1037.50 × 1.19 = 1234.625, which rounds half-up). It would also pin down the rounding behavior.

I noticed that `calc_net` and `calc_vat` have terse names (`t`, `i`) and no type hints. I left them alone because they're outside this task.
