I added `format_invoice_total` at the bottom of `billing/invoice.py`. It reuses `invoice_total` and `format_currency`, so there is no new formatting logic.

```diff
 def invoice_total(items) -> Decimal:
     return calc_net(items) + calc_vat(items)
+
+
+def format_invoice_total(items) -> str:
+    return format_currency(invoice_total(items))
```

For a gross total of `Decimal("1234.50")` it returns `1.234,50 EUR`. I traced that through `format_currency`'s separator swapping by hand, but I haven't run it, so please run your tests.

- **Currency:** it uses `format_currency`'s default (`"EUR"`). I didn't add a currency parameter, since the footer only needs EUR today. It's a one-line change if that ever differs.
- **Rounding:** `invoice_total` doesn't round, and `format_currency` rounds half-up to cents once at the end. If the invoice lines elsewhere (or the PDF body) round VAT separately, the footer could differ by a cent from the sum shown there. Worth a quick check against how the PDF body computes its figures.
- **Tests:** I didn't see a test file, so I didn't add one. If you have one for this module, a case like a single item with price `1234.50`, qty `1` would need the net `1234.50` and VAT `234.555`, which rounds to `1.469,06 EUR`. That makes it a useful rounding check.
