Ich habe am Ende von `billing/invoice.py` eine Funktion ergänzt, die `invoice_total` mit dem vorhandenen `format_currency` verbindet. Eine eigene Formatierungslogik brauchte es nicht (G5).

```diff
 def invoice_total(items) -> Decimal:
     return calc_net(items) + calc_vat(items)
+
+
+def format_invoice_total(items) -> str:
+    return format_currency(invoice_total(items))
```

Ein Beispiel: Bei Positionen mit Netto 1000,00 liefert `format_invoice_total(items)` den String `"1.190,00 EUR"`.

Ich konnte nichts ausführen und kenne eure Testdateien nicht. Ein passender Test wäre:

```python
def test_format_invoice_total_returns_gross_as_german_currency_string():
    items = [Item(price=Decimal("100"), qty=10)]
    assert format_invoice_total(items) == "1.190,00 EUR"
```

`Item` steht hier für euren Positionstyp.

Beim Lesen von `format_currency` ist mir ein Problem aufgefallen, das ich nicht angefasst habe: Die Kette `replace(",", "X")…replace("X", ".")` läuft über den ganzen String, also auch über den Währungscode. Eine Währung mit `X` im Code, etwa `XOF`, würde zu `.OF`. Für `EUR` ist das unkritisch. Wenn ihr mehrere Währungen unterstützen wollt, sollte nur die Zahl umgeformt und der Code danach angehängt werden. Sagt Bescheid, falls ich das ändern soll.
