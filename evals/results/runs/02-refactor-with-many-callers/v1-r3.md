```ts
const BOOK_MEMBER_FACTOR = 0.9;
const DEFAULT_MEMBER_FACTOR = 0.95;
const SAVE10_COUPON = "SAVE10";
const SAVE10_AMOUNT = 10;

export function getPrice(p: any, isMember: boolean, coupon?: string) {
  const memberPrice = isMember ? applyMemberDiscount(p.price, p.category) : p.price;
  const finalPrice = coupon === SAVE10_COUPON ? applySave10(memberPrice) : memberPrice;
  return roundToCents(finalPrice);
}

function applyMemberDiscount(price: number, category: string) {
  const factor = category === "books" ? BOOK_MEMBER_FACTOR : DEFAULT_MEMBER_FACTOR;
  return price * factor;
}

function applySave10(price: number) {
  return Math.max(price - SAVE10_AMOUNT, 0);
}

function roundToCents(price: number) {
  return Math.round(price * 100) / 100;
}
```

**What changed**
- The nested `if`/`else` blocks became three small functions, each doing one thing at one level of abstraction. `getPrice` now reads top-down as: member discount, coupon, rounding (G30, G34).
- Magic numbers (`0.9`, `0.95`, `10`, `"SAVE10"`) are now named constants (G25).
- The duplicated `isMember` branch is gone. Only the factor differed, so it's now one ternary (G5).
- `if (coupon) { if (coupon == "SAVE10") … }` collapsed into one comparison. An empty or undefined coupon never equals `"SAVE10"`, so the outcome is the same.
- The clamp `if (price < 0) price = 0` became `Math.max(price - 10, 0)`. The results match, including for `NaN`.
- `==` became `===`. For string comparison this is identical, as long as `category` is a primitive string or `undefined`.
- Mutable `let price` reassignments are replaced by `const` values.

**Unchanged on purpose**
- The export name, parameter list, and return type are the same, so the ~40 call sites are unaffected.
- I kept `p: any` because I can't see the callers. Narrowing it to something like `{ price: number; category?: string }` would be the next cleanup (F1, G3). It could cause compile errors at call sites that pass other shapes, so it should be a separate step with a typecheck.
