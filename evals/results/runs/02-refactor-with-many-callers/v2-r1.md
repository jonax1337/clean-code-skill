Here is the refactor. The signature and export are unchanged, so the 40 call sites are unaffected.

```ts
const BOOK_MEMBER_MULTIPLIER = 0.9;
const DEFAULT_MEMBER_MULTIPLIER = 0.95;
const SAVE10_COUPON = "SAVE10";
const SAVE10_DISCOUNT = 10;

export function getPrice(p: any, isMember: boolean, coupon?: string) {
  let price = p.price;

  if (isMember) {
    price *= memberMultiplier(p.category);
  }
  if (coupon === SAVE10_COUPON) {
    price = Math.max(price - SAVE10_DISCOUNT, 0);
  }

  return roundToCents(price);
}

function memberMultiplier(category: string): number {
  return category === "books" ? BOOK_MEMBER_MULTIPLIER : DEFAULT_MEMBER_MULTIPLIER;
}

function roundToCents(amount: number): number {
  return Math.round(amount * 100) / 100;
}
```

**What changed (G25, G28, G30, G34):**
- Magic numbers and the coupon code are now named constants.
- The duplicated `isMember` branches are collapsed. Only the multiplier differs by category, so that is the only thing that varies.
- The nested `if (coupon) { if (coupon == ...) }` is a single check. The truthiness test was redundant, because `"SAVE10"` is the only value that can match.
- The manual clamp is now `Math.max(..., 0)`.
- Rounding has a name.
- The order of operations is the same (member multiplier, then coupon, then clamp, then round), so floating-point results are identical.

**Behavior notes:**
- I changed `==` to `===`. For string categories the result is identical. It would only differ if `category` were a non-string object that coerces to `"books"`, which I'd consider a bug anyway. If you want zero risk, revert that one operator.
- I left `p: any` as is. Tightening it (for example to `{ price: number; category?: string }`) could cause compile errors at call sites I can't see, so it should be a separate change once you can check them.
