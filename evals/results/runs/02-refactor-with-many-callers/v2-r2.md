Here's the refactor. The signature, parameter order and return type are unchanged, so the ~40 call sites are unaffected.

```ts
const BOOK_MEMBER_MULTIPLIER = 0.9;
const DEFAULT_MEMBER_MULTIPLIER = 0.95;
const SAVE10_COUPON = "SAVE10";
const SAVE10_AMOUNT = 10;

export function getPrice(p: any, isMember: boolean, coupon?: string) {
  const memberPrice = isMember
    ? p.price * memberMultiplier(p.category)
    : p.price;
  const finalPrice = coupon === SAVE10_COUPON
    ? Math.max(0, memberPrice - SAVE10_AMOUNT)
    : memberPrice;

  return roundToCents(finalPrice);
}

function memberMultiplier(category: string): number {
  return category === "books" ? BOOK_MEMBER_MULTIPLIER : DEFAULT_MEMBER_MULTIPLIER;
}

function roundToCents(amount: number): number {
  return Math.round(amount * 100) / 100;
}
```

**What changed**
- The nested `if`/`else` blocks are now flat expressions. The two duplicated member branches differed only by the multiplier, so they became `memberMultiplier` (G5).
- The magic numbers `0.9`, `0.95`, `10` and `"SAVE10"` are named constants (G25).
- The clamp `if (price < 0) price = 0` became `Math.max(0, …)`. The order is unchanged: member discount, then coupon, then rounding.
- Rounding is extracted as `roundToCents`, so the main function reads as three steps at one level of abstraction (G34).
- The mutable `price` variable is gone.

**Things to check**

- `category == "books"` is now `===`. For string categories this is identical. It would only differ if `category` were a non-string object whose `toString()` returns `"books"`, which seems very unlikely. If you want strict equivalence, switch it back to `==`.
