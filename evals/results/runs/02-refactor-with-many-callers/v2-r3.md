Here's the refactor. The exported name, parameters and return type are unchanged, so the 40 call sites are unaffected.

```ts
const BOOK_MEMBER_MULTIPLIER = 0.9;
const DEFAULT_MEMBER_MULTIPLIER = 0.95;
const SAVE10_COUPON = "SAVE10";
const SAVE10_AMOUNT = 10;

export function getPrice(p: any, isMember: boolean, coupon?: string) {
  let price = p.price;

  if (isMember) {
    price *= memberMultiplier(p.category);
  }
  if (coupon === SAVE10_COUPON) {
    price = Math.max(0, price - SAVE10_AMOUNT);
  }

  return roundToCents(price);
}

function memberMultiplier(category: string): number {
  return category === "books" ? BOOK_MEMBER_MULTIPLIER : DEFAULT_MEMBER_MULTIPLIER;
}

function roundToCents(amount: number): number {
  return Math.round(amount * 100) / 100;
}
```

**What changed**
- The duplicated `isMember` branches are now a single check, and the category-specific rate lives in `memberMultiplier` (G5).
- The magic numbers and the coupon code are named constants (G25).
- The nested coupon `if`s and the manual clamp are now one condition and `Math.max(0, …)`. It gives the same result, including for `NaN`.
- Rounding is extracted into `roundToCents`, so `getPrice` reads at one level of abstraction (G34).

**Things to check**
- `==` became `===` for `"books"` and `"SAVE10"`. This only differs if `category` is a `String` object or a one-element array like `["books"]`, which seems unlikely. If any caller does that, tell me and I'll restore `==`.
- I left `p: any` alone. Tightening it (e.g. `{ price: number; category?: string }`) is a good follow-up, but it could surface type errors across the 40 callers, so it should be its own change.
