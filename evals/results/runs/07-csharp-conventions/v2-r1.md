```csharp
public interface ICustomerRepository
{
    Task<Customer?> GetByIdAsync(Guid id, CancellationToken ct);
    Task<Customer?> GetByEmailAsync(string email, CancellationToken ct);
    Task AddAsync(Customer customer, CancellationToken ct);
}

public sealed class SqlCustomerRepository : ICustomerRepository
{
    private readonly DbContext _db;

    public SqlCustomerRepository(DbContext db) => _db = db;

    public Task<Customer?> GetByIdAsync(Guid id, CancellationToken ct) =>
        _db.Set<Customer>().FindAsync(new object[] { id }, ct).AsTask();

    public Task<Customer?> GetByEmailAsync(string email, CancellationToken ct) =>
        _db.Set<Customer>().FirstOrDefaultAsync(c => c.Email == email, ct);

    public async Task AddAsync(Customer customer, CancellationToken ct)
    {
        _db.Add(customer);
        await _db.SaveChangesAsync(ct);
    }
}
```

Notes:

- It mirrors `SqlOrderRepository` exactly (same constructor, `FindAsync` for id lookup, add-then-save), so the two stay consistent. The `I` prefix follows your existing C# convention.
- `FirstOrDefaultAsync` needs `using Microsoft.EntityFrameworkCore;`, which you likely already have for `DbContext`.
- I assumed `Customer` has a string `Email` property. I couldn't see the type, so adjust if it's named differently or is a value object.
- Email matching is as case-sensitive as your database collation. SQL Server's default is case-insensitive, but PostgreSQL's is not. If you need case-insensitive lookup everywhere, normalize emails on write (e.g., lowercase) and in the query rather than calling `ToLower()` in the predicate, which defeats index use.
- I haven't compiled or run anything here, and I didn't add tests. If you have repository tests for orders, a matching set for customers (especially a not-found email returning `null`) would be a good follow-up.
- Don't forget to register `ICustomerRepository` in your DI setup alongside the order repository.
