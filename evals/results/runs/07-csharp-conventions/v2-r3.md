```csharp
public interface ICustomerRepository
{
    Task<Customer?> GetByIdAsync(Guid id, CancellationToken ct);
    Task<Customer?> GetByEmailAsync(string email, CancellationToken ct);
    Task AddAsync(Customer customer, CancellationToken ct);
}

public sealed class SqlCustomerRepository : ICustomerRepository
{
    private readonly DbContext _db;

    public SqlCustomerRepository(DbContext db) => _db = db;

    public Task<Customer?> GetByIdAsync(Guid id, CancellationToken ct) =>
        _db.Set<Customer>().FindAsync(new object[] { id }, ct).AsTask();

    public Task<Customer?> GetByEmailAsync(string email, CancellationToken ct) =>
        _db.Set<Customer>().FirstOrDefaultAsync(c => c.Email == email, ct);

    public async Task AddAsync(Customer customer, CancellationToken ct)
    {
        _db.Add(customer);
        await _db.SaveChangesAsync(ct);
    }
}
```

`FirstOrDefaultAsync` needs `using Microsoft.EntityFrameworkCore;` if it isn't already imported.

Things to check, since I can't see your `Customer` type or schema:

- **Property name:** I assumed `Customer.Email` is a `string`. If it's a value object or named differently, adjust the predicate.
- **Case sensitivity:** `==` is translated to SQL, so matching follows the column's collation. SQL Server's default is case-insensitive, but PostgreSQL and SQLite are case-sensitive. If emails aren't normalized on write, you may want to lowercase them on save and in the lookup.
- **Uniqueness:** `FirstOrDefaultAsync` assumes at most one customer per email. A unique index on `Email` would enforce that, and it would also make the lookup fast.
- **DI registration:** add `ICustomerRepository` → `SqlCustomerRepository` next to the order repository's registration.
