```csharp
using Microsoft.EntityFrameworkCore;

public interface ICustomerRepository
{
    Task<Customer?> GetByIdAsync(Guid id, CancellationToken ct);
    Task<Customer?> GetByEmailAsync(string email, CancellationToken ct);
    Task AddAsync(Customer customer, CancellationToken ct);
}

public sealed class SqlCustomerRepository : ICustomerRepository
{
    private readonly DbContext _db;

    public SqlCustomerRepository(DbContext db) => _db = db;

    public Task<Customer?> GetByIdAsync(Guid id, CancellationToken ct) =>
        _db.Set<Customer>().FindAsync(new object[] { id }, ct).AsTask();

    public Task<Customer?> GetByEmailAsync(string email, CancellationToken ct) =>
        _db.Set<Customer>().FirstOrDefaultAsync(customer => customer.Email == email, ct);

    public async Task AddAsync(Customer customer, CancellationToken ct)
    {
        _db.Add(customer);
        await _db.SaveChangesAsync(ct);
    }
}
```

- **Mirrored structure:** The interface, class shape, constructor and `AddAsync` follow `SqlOrderRepository` exactly, so the two repositories read the same way (G11).
- **Naming:** I used `GetByEmailAsync` rather than `FindByEmail...` to keep one word per concept, matching the existing `GetByIdAsync`.
- **Nullable return:** `GetByEmailAsync` returns `Customer?`, like `GetByIdAsync`, so callers handle "not found" the same way in both repositories. If you later want to avoid null returns, a Special-Case object or a `CustomerNotFoundException` would be the alternative, but that would change the order repository too, so I left it alone.
- **Assumptions:** `Customer` has a string `Email` property and is registered in the `DbContext`.
- **Case sensitivity:** Matching is case-sensitive or not depending on the database collation. If you need case-insensitive lookup regardless of collation, normalize emails on write (for example, lower-case them in `Customer`) and add a unique index on `Email`. I didn't add either, since you asked only for the repository.

I haven't compiled or tested this. A natural first test is `GetByEmailAsync` returning `null` for an unknown email and the matching customer after `AddAsync`.
