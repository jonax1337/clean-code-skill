```csharp
public interface ICustomerRepository
{
    Task<Customer?> GetByIdAsync(Guid id, CancellationToken ct);
    Task<Customer?> GetByEmailAsync(string email, CancellationToken ct);
    Task AddAsync(Customer customer, CancellationToken ct);
}

public sealed class SqlCustomerRepository : ICustomerRepository
{
    private readonly DbContext _db;

    public SqlCustomerRepository(DbContext db) => _db = db;

    public Task<Customer?> GetByIdAsync(Guid id, CancellationToken ct) =>
        _db.Set<Customer>().FindAsync(new object[] { id }, ct).AsTask();

    public Task<Customer?> GetByEmailAsync(string email, CancellationToken ct) =>
        _db.Set<Customer>().FirstOrDefaultAsync(customer => customer.Email == email, ct);

    public async Task AddAsync(Customer customer, CancellationToken ct)
    {
        _db.Add(customer);
        await _db.SaveChangesAsync(ct);
    }
}
```

`FirstOrDefaultAsync` needs `using Microsoft.EntityFrameworkCore;`.

- **Naming:** I used `GetByEmailAsync` to match `GetByIdAsync` (one word per concept, N1/G11), and the structure mirrors the order repository, as the team convention suggests.
- **Assumption:** `Customer` has a `string Email` property. If `Email` is a value object, the predicate needs adjusting.
- **Case sensitivity:** whether `==` matches case-insensitively depends on your database collation. If emails should be unique regardless of case, normalize them when saving (for example, lowercase) and compare against the normalized value. Also add a unique index on `Email`.
- **Null returns:** the skill advises against returning `null`, but I kept `Customer?` to stay consistent with `IOrderRepository`. If you want to move away from it, that is better done for both repositories together, for example with a `CustomerNotFoundException` or a `TryGet…` style, and I haven't touched the order side.
- **Duplication (G5):** the two repositories now share the same `GetByIdAsync` and `AddAsync` shape. With only two they are fine, but if a third appears, a generic `SqlRepository<TEntity>` base would be worth extracting.
