Customers with no orders hit two separate edge cases (G3):

- `average([])` computes `0 / 0`, which is `NaN`, so `.toFixed(2)` gives `"NaN"`.
- `Math.max()` with no arguments returns `-Infinity`.

I fixed it with a special case in `summarize`, so callers don't have to handle empty input themselves (G33).

**Test first** (add to `stats.test.js`):

```js
describe('summarize', () => {
  test('returns a zero summary for a customer without orders', () => {
    expect(summarize([])).toEqual({ count: 0, avg: '0.00', max: 0 });
  });
});
```

If `summarize` isn't imported there yet, use `const { summarize } = require('./stats');`.

**Fix** (`stats.js`):

```js
const EMPTY_SUMMARY = Object.freeze({ count: 0, avg: '0.00', max: 0 });

function average(values) {
  let sum = 0;
  for (const v of values) sum += v;
  return sum / values.length;
}

function summarize(orders) {
  if (orders.length === 0) return EMPTY_SUMMARY;

  const amounts = orders.map(o => o.amount);
  return {
    count: orders.length,
    avg: average(amounts).toFixed(2),
    max: Math.max(...amounts),
  };
}

module.exports = { average, summarize };
```

- `avg` stays a string (`'0.00'`), the same type as in the non-empty case, so the dashboard code doesn't need to change.
- I chose `max: 0` for "no orders". If the dashboard should show a dash or "n/a" instead, the constant is the only place to change.
- I left `average` alone because nothing else in the code you showed calls it with an empty list. If other callers might, it needs its own decision, since `average([])` still returns `NaN`.
