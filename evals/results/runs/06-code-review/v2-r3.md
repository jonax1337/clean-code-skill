## PR review: `import_users`

### Must fix

**1. Off-by-one drops the last data row (correctness)**
```python
for i in range(1, len(rows) - 1):   # skip header
```
`range(1, len(rows) - 1)` stops one row early, so the final row is never imported. With `rows = [header, a, b]` only `a` is processed. Iterate the data rows directly instead: `enumerate(rows[1:], start=2)`.

**2. `except Exception: pass` swallows everything (G4, section 7)**
```python
except Exception:
    pass
```
This hides short rows (`IndexError`), DB failures, and mailer failures. A failed `db.save` produces no signal, and the caller can't tell "imported 40 of 100" from "imported 100". Worse, if `mailer.send` raises after `db.save` succeeded, the user is persisted but missing from `imported`, so the return value no longer matches the DB. Fix:
- Let `db.save` errors propagate, or collect them with row context.
- Handle malformed rows explicitly, not through a blanket catch.
- Append to `imported` right after the save, before the mail, and handle the mailer's specific error separately.

**3. Reimplements `is_valid_email` (G5)**
```python
if "@" not in email or len(email) > 254:
```
You already have `utils/validation.is_valid_email`. This inline check is weaker (`"@"` and `"a@"` pass) and will drift from the shared rule. Use the helper. Check that it covers the 254 limit; if not, add it there, not here. Invalid rows are also skipped silently, so log them with the line number.

### Should fix

**4. Magic indices (G25):** `row[0]`, `row[1]`, `row[2]` say nothing about the columns. Unpack into `first_name, last_name, raw_email`.

**5. Commented-out code (C5):** delete `# old version: ...`. Git has it. The `# skip header` comment also goes away once the loop uses `rows[1:]` with a short note.

**6. Flag argument `send_welcome` (F3):** the function both imports and sends mail. It's a public signature, so I wouldn't change it in this PR. Consider a follow-up where callers send welcome mails for the returned users.

### Suggested shape
```python
import logging

from utils.validation import is_valid_email

logger = logging.getLogger(__name__)


def import_users(rows, send_welcome=False):
    imported = []
    for line_number, row in enumerate(rows[1:], start=2):  # rows[0] is the header
        try:
            first_name, last_name, raw_email = row[:3]
        except ValueError:
            logger.warning("Skipping line %d: expected 3 columns, got %d", line_number, len(row))
            continue

        email = raw_email.strip().lower()
        if not is_valid_email(email):
            logger.warning("Skipping line %d: invalid email %r", line_number, email)
            continue

        user = User(name=f"{first_name} {last_name}", email=email)
        db.save(user)  # failures propagate: don't report a partial import as success
        imported.append(user)

        if send_welcome:
            mailer.send(email, "Welcome!", WELCOME_TEMPLATE)
    return imported
```
One decision is yours: should a mailer failure abort the import? If not, catch the mailer's specific exception around `mailer.send` and log it with the email. Don't use a blanket `except Exception`.
