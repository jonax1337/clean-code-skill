## Review: `import_users`

### Bugs

1. **Off-by-one drops the last row (G3).** `range(1, len(rows) - 1)` stops one row early, so the final user is never imported. Use `rows[1:]`.
2. **`except Exception: pass` swallows every error (Ch. 7).**
   - A DB outage, a short row (`IndexError`) or a mailer failure all disappear silently.
   - If `mailer.send` fails after `db.save`, the user is persisted but missing from `imported`. The return value then disagrees with the DB.

### Clean-code findings

- **G5 (duplication):** The inline `"@" not in email or len(email) > 254` re-implements `utils.validation.is_valid_email`. Use the existing function. If it doesn't enforce the 254 limit, add that there, not here.
- **F3 (flag argument):** `send_welcome` makes the function do two things. Let the caller send the mail to the returned users.
- **G30/G34 (one thing, one abstraction level):** The function parses, validates, persists and mails.
- **G25 (magic numbers):** `row[0]`, `row[1]`, `row[2]` and `254` are unexplained.
- **C5 (commented-out code):** The `# old version:` block should be deleted. Git has the history.
- **C3 (redundant comment):** `# skip header` goes away once the code says so (`rows[1:]`).
- **G28/G29:** The negated compound condition hides intent. `is_valid_email(...)` states it directly.

### Suggested version

```python
from utils.validation import is_valid_email

FIRST_NAME_COLUMN = 0
LAST_NAME_COLUMN = 1
EMAIL_COLUMN = 2


def import_users(rows):
    rows_without_header = rows[1:]
    imported = []
    for row in rows_without_header:
        if is_valid_email(email_of(row)):
            imported.append(save_user(row))
    return imported


def send_welcome_mail(user):
    mailer.send(user.email, "Welcome!", WELCOME_TEMPLATE)


def save_user(row):
    user = User(name=f"{row[FIRST_NAME_COLUMN]} {row[LAST_NAME_COLUMN]}", email=email_of(row))
    db.save(user)
    return user


def email_of(row):
    return row[EMAIL_COLUMN].strip().lower()
```

Callers that used `send_welcome=True` become:

```python
for user in import_users(rows):
    send_welcome_mail(user)
```

### Notes and open decisions

- **Error policy:** I let DB and malformed-row errors propagate. If you want a bulk import to continue past bad rows, catch a specific exception (e.g. an `InvalidRowError` with the row number in the message). Never use a bare `except Exception: pass`.
- **API change:** Removing `send_welcome` breaks existing callers, so grep for usages first.
- **Tests (Rule 1):** The diff has none. At minimum I'd add:
  - last row is imported
  - header is skipped
  - invalid email is skipped
  - empty input returns `[]`
  - a DB failure propagates
- **Net LOC:** The function body shrinks, but the helpers add a few lines. That is fine, since the named helpers buy readability (Rule 3 before Rule 4).
