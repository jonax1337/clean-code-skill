# Review: `import_users`

## Bugs

1. **Off-by-one (G3):** `range(1, len(rows) - 1)` never processes the last row. Every import silently loses one user. Use `rows[1:]`.
2. **Swallowed errors:** `except Exception: pass` hides every failure: short rows (`IndexError`), DB errors, mailer errors. Worse, if `mailer.send` fails after `db.save`, the user is persisted but missing from `imported`, so the state is inconsistent and nobody knows.

## Clean-code violations

- **G5 (duplication):** The inline `"@" not in email or len(email) > 254` re-implements `is_valid_email`, and does it more weakly. Use the existing function.
- **G25 (magic numbers):** `254` and the column indices `0/1/2` need names.
- **F3 (flag argument):** `send_welcome` makes the function do two things. Split it.
- **G30/G34 (one thing, one abstraction level):** Parsing, validating, persisting and mailing all happen in one loop body.
- **C5 (commented-out code):** Delete `# old version: ...`. Version control has it.
- **C3:** `# skip header` is better expressed in code (`rows[1:]`).
- **Smell:** `range(len(...))` with an index is noisier than iterating the rows directly.

## Suggested rewrite

```python
from utils.validation import is_valid_email

FIRST_NAME, LAST_NAME, EMAIL = 0, 1, 2


def import_users(rows):
    data_rows = rows[1:]
    imported = []
    for row in data_rows:
        if has_valid_email(row):
            imported.append(save_user(row))
    return imported


def send_welcome_mails(users):
    for user in users:
        mailer.send(user.email, "Welcome!", WELCOME_TEMPLATE)


def has_valid_email(row):
    return len(row) > EMAIL and is_valid_email(email_of(row))


def save_user(row):
    user = User(name=f"{row[FIRST_NAME]} {row[LAST_NAME]}", email=email_of(row))
    db.save(user)
    return user


def email_of(row):
    return row[EMAIL].strip().lower()
```

Callers that used `send_welcome=True` become:

```python
send_welcome_mails(import_users(rows))
```

## Notes

- **Behavior change:** Invalid emails and short rows are still skipped, but DB errors now propagate instead of vanishing. If you really want per-row tolerance, catch the specific exception, log it with the row number, and collect the failures. Don't use a bare `pass`.
- **Check `is_valid_email`:** I assumed it doesn't strip or lowercase, so I kept `email_of`. If it does, drop the duplication there too.
- **Tests I'd expect in this PR:**
  - the last row is imported
  - a header-only input returns `[]`
  - an empty list returns `[]`
  - an invalid email is skipped
  - a row with fewer than 3 columns is skipped
  - mail is sent only through `send_welcome_mails`
