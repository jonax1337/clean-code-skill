## Review

### Must fix

**1. Off-by-one drops the last row.** `range(1, len(rows) - 1)` stops before the final element, so the last data row is never imported. Use `rows[1:]` (or `enumerate(rows[1:], start=2)` if you want line numbers).

**2. `except Exception: pass` swallows every failure.** This is the biggest problem. A DB outage, a bug in `User(...)`, a short row (`IndexError`) and a mailer timeout all vanish silently, and the caller gets a partial list with no hint of what went wrong. It also leaves inconsistent state. If `mailer.send` raises after `db.save`, the user is persisted but never appended to `imported`. Narrow the `try` to what you can actually handle, and log with row context for anything you skip.

**3. Reimplements `is_valid_email` (G5).** `"@" not in email or len(email) > 254` is a weaker copy of the helper you already have. Use `is_valid_email`. Since it is probably stricter, check that it doesn't reject rows you accept today.

### Should fix

**4. Invalid rows are skipped silently.** `continue` gives the caller no way to know that rows were dropped. At minimum, log the line number and reason.

**5. Flag argument `send_welcome` (F3) and mixed responsibilities (G30).** The function parses, validates, persists and notifies. Sending mail is better done by the caller (`for user in imported: ...`). Changing that alters the public signature, so I've left it in the sketch below and flagged it here for you to decide.

**6. Magic indexes `row[0]`, `row[1]`, `row[2]` (G25).** Name them with constants, or use `csv.DictReader` if the source allows it.

**7. Commented-out code (C5).** Delete `# old version: ...`, since git has it. The `# skip header` comment is fine, but `rows[1:]` with a short comment makes the intent clearer.

### Tests

I see no tests in the PR. Please add ones for the last row being imported, an invalid email being skipped and logged, a `db.save` failure not being swallowed, and `send_welcome=True` still returning the user if the mailer fails (T5/T6, since bugs cluster here).

### Suggested shape

```python
import logging

from utils.validation import is_valid_email

logger = logging.getLogger(__name__)

FIRST_NAME, LAST_NAME, EMAIL = 0, 1, 2


def import_users(rows, send_welcome=False):
    imported = []
    for line_no, row in enumerate(rows[1:], start=2):  # rows[0] is the header
        email = row[EMAIL].strip().lower()
        if not is_valid_email(email):
            logger.warning("Skipping line %d: invalid email %r", line_no, email)
            continue

        user = User(name=f"{row[FIRST_NAME]} {row[LAST_NAME]}", email=email)
        db.save(user)  # failures propagate: a broken DB should stop the import
        imported.append(user)

        if send_welcome:
            try:
                mailer.send(email, "Welcome!", WELCOME_TEMPLATE)
            except MailerError:  # use the mailer's real exception type
                logger.exception("Welcome mail failed for line %d", line_no)
    return imported
```

Two behavior decisions are baked in here, so please confirm them:

- **DB errors now propagate.** If you would rather continue past a bad row, catch the specific exception around `db.save` and log it.
- **Short rows raise `IndexError`.** If malformed rows are expected input, check `len(row)` explicitly and skip with a log line.

### What's good

- Normalizing with `strip().lower()` before validating and saving is the right order.
- Returning only the successfully imported users is a clear contract. Keep it.
