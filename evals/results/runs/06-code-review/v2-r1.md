## Review

I haven't run anything. This is from reading the diff.

### Must fix

**1. Off-by-one drops the last row.** (correctness)
`for i in range(1, len(rows) - 1)` stops one row early, so the final data row is never imported. For a header plus one user, nothing is imported at all.
Fix: iterate `rows[1:]`, which also makes the `# skip header` comment unnecessary.

**2. `except Exception: pass` swallows every failure.** (Ch. 7, G4-style silent failure)
This hides `IndexError` from short rows, `db.save` failures and `mailer.send` failures. The import reports success while silently losing data. It also leaves inconsistent state: if `mailer.send` raises after `db.save`, the user is persisted but missing from `imported`.
Fix: remove the blanket `try`. If skipping bad rows is intended, handle only the specific case (invalid email), and log it with the row number and reason. Let unexpected errors propagate, or collect them with context.

**3. Duplicated and weaker email validation.** (G5)
`"@" not in email or len(email) > 254` reimplements `is_valid_email` from `utils/validation.py`, and badly: `"@"` and `"a@"` pass. Use the existing helper. Check that it also enforces the 254 limit, so you don't lose that rule.

### Should fix

**4. Silent `continue` on invalid email.** The caller can't tell how many rows were skipped or why. At minimum log a warning with the row number.

**5. Magic indexes.** (G25) `row[0]`, `row[1]` and `row[2]` say nothing about the columns. Use named constants, or `csv.DictReader` if the source allows.

**6. Commented-out code.** (C5) Delete `# old version: ...`. Git history keeps it.

### Consider

- **Flag argument `send_welcome`** (F3) mixes importing with notifying, so the function does two things (G30). Since changing the public signature is out of scope here, I'd leave it and mention it as a follow-up.
- Build the name with an f-string: `f"{row[FIRST]} {row[LAST]}"`. Decide whether to `.strip()` the name parts, since an empty last name currently leaves a trailing space.

### Suggested shape

```python
import logging

from utils.validation import is_valid_email

logger = logging.getLogger(__name__)

FIRST_NAME_COL, LAST_NAME_COL, EMAIL_COL = 0, 1, 2


def import_users(rows, send_welcome=False):
    imported = []
    for line_no, row in enumerate(rows[1:], start=2):
        email = row[EMAIL_COL].strip().lower()
        if not is_valid_email(email):
            logger.warning("Skipping row %d: invalid email %r", line_no, email)
            continue
        user = User(name=f"{row[FIRST_NAME_COL]} {row[LAST_NAME_COL]}", email=email)
        db.save(user)
        if send_welcome:
            mailer.send(email, "Welcome!", WELCOME_TEMPLATE)
        imported.append(user)
    return imported
```

This is a deliberate behavior change: DB and mail errors now propagate instead of vanishing. The team should confirm that's what they want, and whether a mail failure should roll back or keep the saved user.

### Tests to request (T5, T6)

- Header plus one valid row imports exactly one user (regression for the off-by-one).
- An invalid email is skipped and doesn't affect other rows.
- A `db.save` failure is not silently ignored.
- With `send_welcome=True`, the mailer is called once per imported user and not for skipped rows.

### What's good

The email normalization (`strip().lower()`) is sensible, and returning the imported users keeps the function easy to test.
