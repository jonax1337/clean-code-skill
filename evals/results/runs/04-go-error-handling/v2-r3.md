```go
func (s *Server) handleGetUser(w http.ResponseWriter, r *http.Request) {
	id, err := strconv.Atoi(r.URL.Query().Get("id"))
	if err != nil {
		http.Error(w, "invalid user id", http.StatusBadRequest)
		return
	}

	user, err := s.db.FindUser(r.Context(), id)
	if errors.Is(err, store.ErrNotFound) {
		http.Error(w, "user not found", http.StatusNotFound)
		return
	}
	if err != nil {
		log.Printf("find user %d: %v", id, err)
		http.Error(w, "internal server error", http.StatusInternalServerError)
		return
	}

	w.Header().Set("Content-Type", "application/json")
	if err := json.NewEncoder(w).Encode(user); err != nil {
		log.Printf("encode response for user %d: %v", id, err)
	}
}
```

You'll need to add `"errors"` to the imports.

**What was wrong**
- `id, _ := strconv.Atoi(...)` swallowed the parse error, so `?id=abc` silently looked up user 0. It now returns 400.
- A `FindUser` error was logged but execution continued, so the handler encoded a zero-value `user` with a 200. Now each failure returns.
- `store.ErrNotFound` is a client-visible condition, not a server fault. It maps to 404 via `errors.Is`, which also matches wrapped errors.
- Any other error is logged with context (operation and id), and the client gets a generic 500 so internals don't leak.
- The `Encode` error was ignored. At that point the status is already sent, so all we can do is log it.

**Behavior changes to be aware of**
- Responses that used to be 200 with a bogus body are now 400, 404 or 500.
- A `Content-Type: application/json` header is now set. This is a small addition, but it's correct for a JSON body.
- Error responses use `http.Error`, which sends plain text. If your API returns JSON errors elsewhere, swap in your existing helper to stay consistent.
