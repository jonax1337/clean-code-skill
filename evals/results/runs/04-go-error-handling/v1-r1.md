```go
func (s *Server) handleGetUser(w http.ResponseWriter, r *http.Request) {
	id, err := parseUserID(r)
	if err != nil {
		http.Error(w, "invalid user id", http.StatusBadRequest)
		return
	}

	user, err := s.db.FindUser(r.Context(), id)
	if err != nil {
		respondToFindUserError(w, id, err)
		return
	}

	respondWithJSON(w, http.StatusOK, user)
}

func parseUserID(r *http.Request) (int, error) {
	raw := r.URL.Query().Get("id")
	id, err := strconv.Atoi(raw)
	if err != nil {
		return 0, fmt.Errorf("parse user id %q: %w", raw, err)
	}
	return id, nil
}

func respondToFindUserError(w http.ResponseWriter, id int, err error) {
	if errors.Is(err, store.ErrNotFound) {
		http.Error(w, "user not found", http.StatusNotFound)
		return
	}
	log.Printf("find user %d: %v", id, err)
	http.Error(w, "internal server error", http.StatusInternalServerError)
}

func respondWithJSON(w http.ResponseWriter, status int, body any) {
	w.Header().Set("Content-Type", "application/json")
	w.WriteHeader(status)
	if err := json.NewEncoder(w).Encode(body); err != nil {
		log.Printf("encode response: %v", err)
	}
}
```

**What changed**

- **Swallowed parse error (G4, G3):** `id, _ := strconv.Atoi(...)` turned `?id=abc` into a lookup for user 0. Bad input now returns `400`, and the parse error carries the offending value as context.
- **Log-and-continue:** the old code logged the `FindUser` error and then encoded a nil user, so the client got a `200` with `null`. Now every error path returns immediately with a proper status.
- **Not found vs. failure:** `store.ErrNotFound` maps to `404` via `errors.Is`, which also works if the error gets wrapped later. Anything else is logged with the operation and id as context and returns a generic `500`, so internals don't leak to the client.
- **Unchecked `Encode`:** its error is now handled. Once the header is written, logging is all you can do, so that is the one place where only logging is correct.
- **Structure (F-rules, G30, G34):** the handler now reads as a short narrative at one abstraction level. Parsing, error mapping, and response writing live in small single-purpose helpers with at most 3 arguments each.
